# AI 협업 가이드

이 문서는 AI 작업자가 이 저장소에서 작업할 때의 절차와 권한 경계를 정의합니다.
코드 작성 규칙은 [`CONTRIBUTING.md`](../../CONTRIBUTING.md)를 원본으로 사용하며 여기서 반복하지 않습니다.

## 규칙 우선순위

1. 현재 사용자의 명시적 지시
2. 연결된 GitHub 이슈의 완료 조건
3. `CONTRIBUTING.md`와 `docs/` 문서
4. 기존 코드의 인접 패턴

서로 충돌하거나 요구사항이 불명확하면 임의로 선택하지 않고 사용자에게 확인합니다.

## 작업 시작

- 파일을 변경하기 전에 `git status`로 기존 변경을 확인합니다. 정상이면 조용히 진행하고, 기존 변경·잘못된 브랜치 등 문제가 있을 때만 알립니다.
- 기본 작업은 `develop`에서 합니다 (1인 운영 — push 마다 CI 검증). `main` 직접 push 는 금지하며, 운영 반영은 승격 PR로만 합니다.
- 범위가 크거나 실험적인 작업은 `<type>/<작업요약>` 브랜치로 분리합니다.
- 기존 변경과 현재 작업을 같은 커밋에 섞지 않습니다.

## 권한 경계

- 로컬 수정과 검증(lint·typecheck·test·build)은 자율적으로 수행합니다.
- 커밋은 사용자가 요청했거나 작업 흐름상 합의된 경우에만 생성합니다.
- push, PR 생성·머지, 이슈 변경 등 GitHub 상태 변경은 사용자 승인 후 수행합니다. 한 번의 승인은 그 작업에만 유효합니다.
- 커밋 메시지에 Co-Authored-By 트레일러를 넣지 않습니다.

## PR

- PR 본문은 `.github/pull_request_template.md` 형식을 그대로 따릅니다. gh CLI 로 만들면 템플릿이 자동 적용되지 않으므로 본문을 직접 템플릿 구조로 작성합니다.
- 체크박스는 사실대로만 체크합니다. 화면을 직접 확인하지 않았으면 "변경 기능 직접 확인"은 미체크로 두고 확인 필요 경로를 기재합니다.
- CI 실패와 리뷰 봇의 actionable 코멘트는 검증 후 반영하고, 반영 커밋 번호로 스레드에 답합니다. 리뷰 내용은 신뢰하지 말고 현재 코드로 직접 검증한 뒤 수정합니다.

## 작업 범위

- 현재 요청의 범위만 변경합니다. 범위 밖 문제를 발견하면 별도 이슈로 제안합니다.
- 계획의 전제가 틀렸거나 범위가 커지면 작업을 멈추고 다시 협의합니다.
- DB 스키마, 인증·권한, API 계약을 바꾸는 변경은 구현 전에 계획을 제시하고 승인받습니다.

## 저장소 특이사항

- `AGENTS.md`의 Next.js 안내 블록은 `next dev`가 자동 재생성합니다. 지우지 말고, Next.js API 사용 전 `node_modules/next/dist/docs/`의 해당 문서를 확인합니다.
- `package-lock.json`에서 `@emnapi/*` 항목이 빠지는 diff는 darwin 플랫폼 노이즈입니다. 커밋하지 말고 되돌립니다. 의존성을 바꾸지 않는 설치는 `npm ci`를 사용합니다.
- 보고·문서·커밋은 한국어로 작성합니다.
